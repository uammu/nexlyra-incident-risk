## Intended use

## Prohibited uses
- Production alerting, paging or auto-remediation before validation on real, consented telemetry.
- Claiming real-world predictive performance from these results.
- Evaluating, ranking or penalising individual engineers or teams.
- Any use that changes customer treatment or SLA obligations by customer_tier.

## Data provenance
- File: nexlyra_ml_incident_dataset_10000.csv, 10,000 rows, 20 columns, sha256 <data/checksums.json>.
- Generated by a simulated probabilistic process. No real company telemetry.
- Time: 30-minute cadence from 2026-01-01. Labels are only known 60 minutes after each event.

## Synthetic-label limitations
- Labels come from a formula, so the model can only learn the simulator, not real incident causes.
- Metrics are NOT evidence of real-world accuracy. Feature importances describe the simulator.
- Real telemetry has bursts, outages, missing data and shifting baselines that are not represented here.

## Privacy and retention
- Dataset has no personal data. If real telemetry is used: no user identifiers or free-text; service, region and tier only.
- Prediction audit logs keep an input hash, not raw inputs. Proposed retention: 90 days; model-change log: 1 year.
- Access to logs limited to the ML owner and on-call lead.

## Ethical / operational considerations
- customer_tier is used as a feature. Check it does not cause lower-tier customers' incidents to be under-alerted.
- Alert fatigue is the main harm: too many false alerts teach people to ignore the system.
